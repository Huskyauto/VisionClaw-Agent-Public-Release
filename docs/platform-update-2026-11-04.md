## Readiness limitations

- The full tenant audit remains incomplete/degraded. A scoped check or independent
  release review must not be relabeled a completed full audit.
- Publication must reconcile the webhook binding column through the managed schema
  diff. No production schema mutation is performed by repository synchronization.
- Production webhook concurrency, real Gmail consent, complete company-package
  delivery and application-wide aggregate metered-AI budget proof are not
  established by a documentation refresh or build.
- GitHub synchronization is separately owner-authorized and does not publish the
  running app. The public repository remains a sanitized mirror, not a private
  database, credentials, uploads or owner-state backup.
- Release verification results must name their actual checked scope; failed or
  blocked checks are not readiness approval.
